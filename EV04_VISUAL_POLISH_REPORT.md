# EV-04 Visual Polish Report

## Результат

Лист персонажа получил лёгкую пергаментную оболочку с коричневой типографикой, тонкими декоративными линиями и единым визуальным языком карточек. Поля и списки остаются обычными редактируемыми формами: декоративные элементы не перекрывают содержимое и не меняют v3 adapter flow.

Отдельно пересмотрен блок характеристик. На desktop он теперь использует сетку 2×3 в узкой колонке основного экрана: название, score и modifier читаются отдельно, а длинные русские названия больше не сжимаются до вертикальных букв. При stacked-layout и на узком экране сетка переходит в 3 и 2 колонки соответственно.

## Что изменено

- `src/modules/character-sheet/styles/character-sheet.css` — добавлены пергаментный фон, рамка и декоративный разделитель, единые токены цвета, карточки и кнопки, focus-состояния, различимые manual/computed/ready/unset badges, сетки magic/inventory, перенос длинного текста, пустые состояния и responsive-правила; блок характеристик переведён в читаемую 2×3 сетку.
- `src/modules/character-sheet/CharacterSheetPage.vue` — вкладки обёрнуты в `.sheet-tabs` для общей рамки и mobile-прокрутки без обрезания подписей.
- `src/modules/character-sheet/components/CharacterSheetHeader.vue` — статусы упорядочены как error → saving → dirty → saved; добавлена семантика `role`/`aria-live`.
- `src/modules/character-sheet/components/AttackList.vue` — manual/computed режим атаки получает отдельный визуальный класс.
- `src/modules/character-sheet/components/CombatStatsFields.vue` — manual/computed режим КД получает отдельный визуальный класс.
- `src/modules/character-sheet/components/SpellcastingSummary.vue` — состояния «Настроено» и «Не настроено» получают разные badge-классы.
- `src/modules/character-sheet/components/InventoryList.vue` — состояние экипировки получает отдельный badge-класс.

Новые зависимости и изображения не добавлялись. Приложенная карта использована как визуальный ориентир: вместо тяжёлой фоновой картинки применены CSS-пергамент и рамка, чтобы текст и поля сохраняли контраст и размер.

## UI-аудит

- Пустые коллекции получили заметную пунктирную область и не схлопывают карточку.
- Длинные описания и свойства переносятся внутри записи; список остаётся обычной вертикальной прокруткой страницы.
- Большие наборы предметов и заклинаний не получают фиксированную высоту и не теряют доступ к действиям.
- Magic на desktop использует две колонки для коллекций, summary и spell slots занимают всю ширину.
- Inventory на desktop использует широкую область для предметов и отдельную карточку денег; названия валют не ломаются в узкой колонке.
- На mobile вкладки прокручиваются горизонтально внутри своей полосы, карточки и редакторы переходят в одну колонку, кнопки действий растягиваются на доступную ширину.
- `focus-visible`, текстовые labels и ARIA-статусы сохранены; цвет не является единственным сигналом состояния.

## Проверки

- `npm run typecheck` — успешно.
- `npm test` — успешно, 27/27.
- `npm run build` — успешно; остались только прежние предупреждения Rollup о `__PURE__` комментариях внутри `@vueuse/core`.
- `git diff --check` — ошибок содержимого нет; предупреждения только о стандартном преобразовании LF/CRLF.
- Ручная browser-проверка через локальный Vite: обычная загрузка, четыре вкладки, desktop-рендер Основного/Магии/Инвентаря/БИО, итоговая сетка характеристик, loader, контролируемая ошибка `?mockLoadError=once` и успешный Retry. На чистом origin (порт 5174) сохранённые данные не скрывали ошибку.
- В консоли браузера ошибок не обнаружено.

## Ограничения

- Полный автоматизированный browser harness не запускался: `tests/character-sheet/browser-check.mjs` требует пакет `playwright`, которого нет в текущих зависимостях; новые зависимости по scope не устанавливались.
- Mobile-правила проверены статически и через responsive CSS-ветки; отдельный runtime-снимок 375px требует доступного Playwright/viewport-инструмента.
- Backend, API, migration layer, v3 adapter, domain helpers и другие репозитории не изменялись.
