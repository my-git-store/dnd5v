# DND5V UI Design v3

## Статус и границы

Документ описывает интерфейс цифрового листа D&D 5e на основе Character v3 из SHEET_DND5E_MODEL_DESIGN.md и текущей архитектуры из SHEET_DND5E_EVOLUTION_PLAN.md.

Это только дизайн интерфейса. Код, Vue-компоненты, storage, API и UI-kit не изменяются. Основой остаются Vue 3, Composition API, TypeScript, mock Character API и localStorage до отдельного этапа подключения Character System.

Главные ограничения интерфейса:

- четыре верхнеуровневые вкладки сохраняются: Основное, Магия, Инвентарь, Личность;
- вычисляемые значения нельзя редактировать как будто это исходные данные;
- manual и computed режимы отображаются явно;
- существующие v2 записи должны открываться через слой миграции;
- интерфейс не содержит backend, multiplayer, realtime или dice engine.

## 1. Desktop layout

### 1.1 Оболочка приложения

Рабочая область ограничена по ширине, чтобы карточки не растягивались дальше удобного расстояния чтения. На широком экране используется сетка из 12 колонок с равномерными промежутками.

Порядок оболочки:

1. Верхняя строка с названием персонажа, краткой identity-информацией и состоянием сохранения.
2. Основная навигация из четырёх вкладок.
3. Контент выбранной вкладки.
4. Постоянная область действий: Сохранить, статус ошибки, Повторить загрузку при необходимости.
5. На desktop кнопка сохранения остаётся видимой без прокрутки длинной формы.

### 1.2 Header

В левой части header:

- имя персонажа;
- race и class/subclass;
- background и alignment короткими подписями;
- необязательный portrait placeholder.

В правой части:

- уровень и experience;
- derived proficiency bonus;
- индикатор manual/computed состояния;
- статус «Изменения не сохранены», «Сохраняется», «Сохранено»;
- основная кнопка Сохранить.

Пустые значения показываются как «Не заполнено», а не как незаметный пробел. Клик по identity-информации переводит пользователя к нужному блоку в Основном.

### 1.3 Вкладка «Основное»

Основное — главный экран персонажа. Его порядок соответствует чтению листа сверху вниз и не заставляет игрока искать базовые значения по разным вкладкам.

#### Верхний ряд

- Identity panel: name, race, class, subclass, level, experience, background, alignment.
- Progression panel: proficiency bonus, hit die, spellcasting ability.
- Derived state: несохранённые изменения и предупреждения неполных данных.

#### Центральная рабочая сетка

Левая колонка:

- шесть характеристик;
- рядом с каждым raw score — крупный вычисляемый modifier;
- короткая подсказка с формулой modifier;
- состояние пустого или некорректного значения.

Центральная колонка:

- saving throws по шести характеристикам;
- переключатели proficiency;
- additional bonus;
- итоговое значение и подпись источника.

Правая колонка:

- skills;
- связанная ability;
- none/proficient/expertise;
- manual/computed режим;
- ручное значение value, если выбран manual;
- итоговый bonus, если выбран computed.

#### Combat и атаки

Под центральной сеткой размещается широкий combat-блок:

- armor class с индикатором manual/computed;
- initiative;
- speed;
- hit points: max/current/temporary;
- hit dice;
- death saves.

Ниже на всю ширину:

- список атак;
- название, тип, ability source;
- proficient;
- attack bonus;
- damage, damage type, properties и range;
- действия редактирования/удаления.

Атаки не скрываются в отдельной вкладке: во время игры они должны быть доступны сразу после combat stats.

### 1.4 Вкладка «Магия»

Порядок блоков:

1. Spellcasting summary:
   - spellcasting ability;
   - spell save DC;
   - spell attack bonus;
   - состояние «Не настроено», если ability не выбрана.
2. Spell slots по уровням 1–9.
3. Заговоры.
4. Известные заклинания.
5. Подготовленные заклинания как отдельный фильтр или состояние списка.

Заговоры и заклинания используют одинаковый визуальный паттерн записи, но уровень и слот отображаются только для заклинаний. Поиск фильтрует локальный список и не меняет данные персонажа.

На desktop списки cantrips и known spells располагаются в две колонки. При большом количестве записей карточка поддерживает компактный режим строки и раскрытие подробностей.

### 1.5 Вкладка «Инвентарь»

Сетка:

- 8 колонок: список предметов;
- 4 колонки: деньги и краткая информация о переносимых вещах.

В строке предмета видны:

- название;
- quantity;
- weight, если задан;
- equipped;
- короткое описание;
- действия.

Редактор открывается встроенно или в существующей modal-системе. Длинное описание раскрывается без изменения списка.

Деньги показываются отдельными полями copper, silver, electrum, gold, platinum. Автоматическая конвертация не выполняется.

### 1.6 Вкладка «Личность»

Для desktop используются две колонки:

- traits и ideals;
- bonds и flaws.

Ниже на всю ширину:

- biography;
- features.

Поля многострочные, но не занимают высоту всей страницы при первом открытии: используются равномерные минимальные размеры и естественное расширение при вводе.

## 2. Mobile layout

### 2.1 Навигация

На узком экране сохраняются четыре вкладки:

- Основное;
- Магия;
- Инвентарь;
- Личность.

Подписи не обрезаются. Если ширины не хватает, вкладки прокручиваются горизонтально; важные действия не скрываются за троеточием.

Header становится двухуровневым:

1. имя, уровень и статус;
2. кнопка сохранения и вкладки.

Кнопка сохранения может быть sticky в нижней части, но не перекрывает поля и учитывает safe area мобильного устройства.

### 2.2 Порядок блоков

#### Основное

1. Имя и identity.
2. Class, subclass, race, background.
3. Level, experience и proficiency bonus.
4. Ability scores с modifiers.
5. Saving throws.
6. Skills.
7. Combat stats.
8. Attacks.

Каждая секция сворачивается только визуально; несохранённый черновик не теряется при закрытии или смене вкладки.

#### Магия

1. Spellcasting summary.
2. Горизонтальная или компактная сетка spell slots.
3. Поиск.
4. Заговоры.
5. Известные заклинания.
6. Фильтр подготовленных.

#### Инвентарь

1. Деньги.
2. Поиск предметов.
3. Список предметов карточками.
4. Добавление/редактирование предмета.
5. Поля quantity, weight и equipped раскрываются внутри карточки.

#### Личность

1. Traits.
2. Ideals.
3. Bonds.
4. Flaws.
5. Biography.
6. Features.

### 2.3 Сценарий игрока на телефоне

Игрок открывает лист и сразу видит имя, уровень и кнопку сохранения. Для проверки атаки он открывает Основное, прокручивает до combat и нажимает нужную запись. Для заклинания он переходит в Магию, видит spell DC/attack сверху, затем фильтрует список. Для изменения предмета он открывает Инвентарь, редактирует количество и возвращается к игре без потери draft.

Ошибки показываются рядом с полем и в компактном alert. Фокус после сохранения остаётся в текущем разделе.

## 3. Компоненты

### 3.1 Контейнеры и существующие компоненты

| Компонент | Роль в v3 |
|---|---|
| CharacterSheetPage.vue | Загрузка, вкладки, общий draft, save/error state |
| CharacterSheetHeader.vue | Identity summary, уровень и сохранение |
| CharacterLoadState.vue | Loader, ошибка и retry |
| CharacterMainTab.vue | Компоновка identity, abilities, saves, skills и combat |
| CharacterMagicTab.vue | Spellcasting и списки магии |
| CharacterInventoryTab.vue | Предметы и деньги |
| CharacterBioTab.vue | Personality и biography |
| useCharacterSheet | Единственный контейнер изменений draft |
| CharacterApi interface | Абстракция mock/будущего источника данных |

Потомки не читают localStorage и не вызывают API напрямую. Они получают данные и отправляют изменения через props/events или согласованные composable-методы.

### 3.2 Переиспользуемый UI-kit

Используются без создания нового UI-kit:

- CBtn для основных и вторичных действий;
- CCard для секций и derived summary;
- CInput для коротких полей и числовых значений;
- CTextarea для biography, traits и описаний;
- CTabs для четырёх верхних вкладок;
- CModal/CModalRender и существующая confirm-система для удаления;
- CAlert для ошибок и предупреждений;
- CLoaderBlock для загрузки;
- EntryActions для одинаковых edit/delete действий;
- EmptyCollection для пустых атак, заклинаний и предметов;
- CollectionSearch для локального поиска;
- MoneyFields для валюты;
- CharacterDetailsFields как существующая база для class/level/experience/AC.

Нативный select допускается для ability source, proficiency и spellcasting ability, если текущий CSelect не обеспечивает нужное поведение.

### 3.3 Новые компоненты дизайна

| Компонент | Ответственность |
|---|---|
| IdentityPanel | name, race, class, subclass, background, alignment |
| RaceFields | RaceProfile и источник расовых данных |
| BackgroundFields | feature, skills, tools, languages, notes |
| ProgressionFields | level, experience, hit die, spellcasting ability |
| DerivedStatsCard | proficiency bonus, passive values и источники |
| AbilityFields | raw scores и modifiers |
| SavingThrowFields | шесть saves, proficiency и additional bonus |
| SkillFields | список и режим manual/computed |
| CombatStatsFields | AC, initiative, speed, HP, hit dice, death saves |
| AttackList | список атак и empty state |
| AttackEditor | manual/computed attack и свойства |
| SpellcastingSummary | ability, DC, attack modifier |
| SpellSlotFields | max/used по уровням |
| SpellList | cantrips, known и prepared filters |
| SpellEditor | подробности spell entry |
| InventoryList | список предметов и поиск |
| InventoryItemEditor | quantity, weight, equipped, description |
| MoneyFields | пять номиналов |
| PersonalityFields | traits, ideals, bonds, flaws, biography, features |
| RestPanel | preview и подтверждение short/long rest действия |

Каждый компонент отвечает за один смысловой блок. Главная страница только соединяет блоки и не содержит расчётов правил.

### 3.4 Границы данных

- Domain helpers рассчитывают modifiers и bonuses.
- Composable хранит draft, saved snapshot, dirty и save state.
- Формы редактируют копию записи.
- Derived fields имеют визуальную подпись «вычисляется».
- Кнопка отмены возвращает локальную копию записи без изменения общего draft.
- Только общий Save записывает Character через CharacterApi.

## 4. UX-сценарии

### 4.1 Создание персонажа

1. Пользователь открывает пустой лист.
2. UI показывает четыре обязательные стартовые области: name, level, abilities и class/race.
3. Пользователь заполняет identity.
4. Устанавливает six ability scores.
5. Выбирает proficiency в saves/skills и при необходимости spellcasting ability.
6. Заполняет combat и attacks вручную.
7. При сохранении валидатор подсвечивает только незаполненные или некорректные поля.
8. После успешного mock save появляется «Сохранено».
9. Перезагрузка открывает те же данные из v3 storage после миграции.

Пустые optional-секции не блокируют сохранение. Уровень, имя и числа с неверным диапазоном блокируют только подтверждение сохранения.

### 4.2 Редактирование и черновик

- Любое изменение помечает лист как dirty.
- Переключение вкладок не сбрасывает draft.
- Встроенный редактор записи работает с копией.
- Отмена редактора не меняет общий Character.
- Удаление требует существующее modal-подтверждение.
- Во время save поля и повторная кнопка Save блокируются.
- Ошибка сохранения оставляет все введённые данные.
- Состояние «Сохранено» показывается только после ответа API.
- При уходе со страницы с dirty draft показывается предупреждение браузера.

### 4.3 Сценарий боя

1. Игрок открывает Основное.
2. В header видит уровень и proficiency bonus.
3. В combat видит AC, initiative, HP и death saves.
4. В атаке видит источник ability, proficiency и computed/manual режим.
5. Для computed-атаки UI показывает формулу и итоговый attack bonus.
6. Для manual-атаки UI показывает исходную строку attackBonus без разбора.
7. Игрок меняет current HP, temporary HP или death save.
8. Игрок редактирует attack damage/properties и сохраняет общий draft.
9. Удаление атаки подтверждается модальным окном.

Dice roll, автоматическое применение урона и боевые состояния не входят в этот интерфейсный этап.

### 4.4 Сценарий магии

1. Пользователь выбирает spellcasting ability.
2. В summary появляются spell save DC и spell attack bonus.
3. Пользователь настраивает max/used spell slots.
4. Добавляет known spell или cantrip.
5. При необходимости отмечает known spell подготовленным.
6. Использует поиск и фильтр prepared.
7. Открывает карточку и редактирует description, range, duration и компоненты.
8. Удаляет запись через modal-confirm.
9. После сохранения переключается на Основное; dirty state сохраняется до общего Save.

Если ability не настроена, DC и attack показываются как «Не настроено». UI не подставляет Charisma автоматически.

### 4.5 Сценарий инвентаря

1. Пользователь открывает Инвентарь.
2. Видит деньги и локальный поиск.
3. Добавляет предмет.
4. Задаёт quantity, weight, description и equipped.
5. Включает/выключает equipped без изменения количества.
6. Редактирует или удаляет предмет.
7. Переключается в Личность или Основное; draft сохраняется.
8. Нажимает общий Save.

Автоматическая перегрузка, стоимость и конвертация денег не показываются как готовые правила. Weight отображается только как введённая информация.

### 4.6 Сценарий отдыха

RestPanel является помощником изменений, а не отдельным источником правил.

#### Short rest

- показывает текущие HP, temporary HP и spent hit dice;
- позволяет вручную отметить потраченные hit dice;
- предлагает ввести результат восстановления HP;
- перед применением показывает preview изменений;
- требует подтверждения;
- не меняет spell slots автоматически.

#### Long rest

- показывает preview: current HP → max HP;
- предлагает сбросить used spell slots в 0;
- показывает восстановление части spent hit dice как отдельную настройку;
- не применяет class-specific исключения без rules adapter;
- требует явного подтверждения.

После подтверждения изменения становятся обычным dirty draft. Они не отправляются отдельно и сохраняются только общей кнопкой Save. Если правила отдыха ещё не подключены, RestPanel работает как последовательный помощник ручного ввода и честно сообщает об ограничении.

## 5. Визуальный стиль

### 5.1 Атмосфера D&D

- светлая пергаментная основа;
- тёмно-коричневый текст и рамки;
- приглушённые красные/золотые акценты для важных состояний;
- тонкие декоративные разделители, не мешающие чтению;
- иконки только как дополнительный сигнал, не вместо текста;
- отсутствие тяжёлых текстур, которые ухудшают контраст и увеличивают размер страницы.

Визуальный стиль продолжает текущую тему проекта, а не заменяет её отдельной дизайн-системой.

### 5.2 Иерархия и читаемость

- имя и уровень — самый заметный заголовок;
- raw score и modifier — соседние, но визуально разные значения;
- computed values имеют подпись источника;
- ручные поля обозначены как «вручную»;
- ошибки располагаются рядом с полем;
- кнопки edit/delete имеют текстовую доступность и понятный focus state;
- длинные тексты не превращаются в мелкий шрифт;
- контраст текста и границ соответствует обычному чтению при слабом освещении.

### 5.3 Цветовые состояния

| Состояние | Представление |
|---|---|
| Derived | Нейтральная светлая карточка и подпись «вычисляется» |
| Manual | Тёплый нейтральный акцент и подпись «вручную» |
| Dirty | Небольшой amber-индикатор рядом с Save |
| Saved | Спокойный зелёный текст без навязчивой анимации |
| Error | Контрастный красный alert и сообщение у поля |
| Disabled | Сниженный контраст, но сохранённая читаемость |

Цвет не является единственным способом передать состояние: используются текст и aria-label.

### 5.4 Доступность

- все поля имеют видимую подпись;
- таб-порядок соответствует порядку блоков;
- modal deletion возвращает фокус на вызвавшую кнопку;
- клавиатура может открыть, подтвердить и отменить любое действие;
- числовые поля не требуют мыши для изменения;
- списки не теряют фокус после локального поиска;
- на мобильном ширина интерактивной цели достаточна для касания;
- пользователь не обязан распознавать цветовую кодировку без текста.

### 5.5 Состояния загрузки и ошибок

- первичная загрузка показывает loader на месте листа;
- ошибка загрузки не показывает пустой персонаж поверх потерянных данных;
- Retry повторяет запрос;
- ошибка save оставляет draft и показывает причину;
- localStorage и mock API не должны создавать незаметные сетевые обращения.

## 6. Проверка будущей реализации

Интерфейс v3 считается соответствующим этому документу, когда:

- desktop показывает identity, abilities, saves, skills, combat и attacks без поиска по странице;
- mobile сохраняет тот же смысловой порядок и не создаёт горизонтального overflow;
- четыре вкладки доступны с клавиатуры;
- manual/computed режимы различимы;
- old v2 data открываются через migration без потери attackBonus и skill.value;
- CRUD атак, заклинаний, заговоров и предметов сохраняет текущие modal-confirm сценарии;
- create/edit/save/reload и error/retry проходят без потери draft;
- spellcasting, slots и prepared filter работают без каталога заклинаний;
- RestPanel требует preview и подтверждение;
- typecheck, тесты и production build проходят без отключения strict TypeScript.

До отдельного задания на реализацию этот документ остаётся UI-дизайном. Компоненты и исходники не изменяются.
