# Nastolka D&D 5: спецификация проекта

`nastolka-dnd-5-sheet` - браузерный лист персонажа D&D 5 с ручным заполнением и локальным сохранением.

README описывает назначение приложения, пользовательские сценарии, модель данных, устройство модулей и ограничения текущей реализации. Общие правила написания кода и работы с репозиторием находятся в [AGENTS.md](AGENTS.md). При изменении возможностей проекта здесь обновляются соответствующие разделы спецификации.

## Назначение и границы приложения

Приложение открывает один лист персонажа и позволяет редактировать его характеристики, боевые параметры, заклинания, снаряжение и биографию.

Текущий лист работает без backend. Авторизация, игровые комнаты, совместное редактирование и серверная синхронизация не подключены. Vue Router, Pinia, Pinia Colada и генерация API через Orval в текущем приложении отсутствуют.

## Пользовательские возможности

В шапке листа редактируются основные сведения о персонаже: имя, вид, класс, подкласс, уровень, опыт и мировоззрение. Здесь же отображается состояние сохранения.

| Раздел | Возможности |
| --- | --- |
| Основное | Шесть характеристик, спасброски, навыки и пользовательские черты |
| Бой | Класс брони, инициатива, скорость, хиты, кости хитов, спасброски от смерти и атаки |
| Магия / Заклинания | Заклинания и заговоры, подготовленные заклинания, ячейки уровней 1-9 и учёт их расходования |
| Инвентарь | Предметы, количество, вес, экипировка, расходование предметов и монеты пяти номиналов |
| БИО | Черты характера, идеалы, привязанности, слабости, биография и дополнительные заметки |

Атаки, заклинания, заговоры, предметы и пользовательские черты удаляются сразу, без подтверждения. Удаление сохраняется вместе с остальными изменениями листа.

Атаки редактируются в раскрывающихся пунктах списка без модального окна. Новые атаки появляются свёрнутыми и раскрываются вручную; изменения полей сразу применяются к листу. Атака содержит название, тип, дистанцию, описание и строки урона. Строки урона можно добавлять и удалять. Каждая строка содержит текст урона (например, `1d8`), свой тип урона, дополнительный целочисленный урон, необязательную характеристику и флаг «Добавлять бонус владения». Поля строки редактируются компонентом `AttackDamageRow`.

Заговоры и заклинания реализованы отдельными модулями: у каждого свой список и своя модальная форма создания и редактирования. У заговоров нет поля уровня; уровни заклинаний ограничены диапазоном 1-9. Фильтр подготовленных записей доступен только для заклинаний.

Создание и редактирование предметов выполняются в `InventoryItemEditorModal`: окно содержит форму и локальный черновик предмета. Изменения передаются списку по кнопке «Применить»; отмена, Escape и закрытие по фону не изменяют инвентарь. Свойства предмета (`properties`) вводятся и хранятся одной строкой.

### Загрузка и сохранение

- При открытии приложение читает сохранённый лист. Если записи нет, создаётся пустой персонаж первого уровня; до первого сохранения он находится только в памяти.
- Обычные изменения сохраняются кнопкой сохранения. Несохранённые изменения определяются сравнением листа с последним сохранённым снимком.
- Изменение расхода ячеек и расходование предметов сохраняются кнопкой сохранения вместе с остальными изменениями листа.
- При закрытии страницы с несохранёнными изменениями приложение запрашивает стандартное предупреждение браузера.
- Ошибки чтения и записи отображаются отдельно. При ошибке загрузки доступны повторная попытка и создание нового персонажа.
- Создание нового персонажа заменяет текущий лист. Если персонаж уже загружен или возникла ошибка загрузки, действие требует подтверждения.
- Выбранная вкладка запоминается в `sessionStorage`; неизвестное значение заменяется на «Основное».

## Игровые расчёты

Ниже зафиксировано поведение текущей реализации. Основные функции находятся в [src/domain](src/domain).

| Показатель | Расчёт |
| --- | --- |
| Модификатор характеристики | `floor((значение - 10) / 2)` |
| Бонус мастерства | +2 на уровнях 1-4, +3 на 5-8, +4 на 9-12, +5 на 13-16, +6 на 17-20 |
| Навык в вычисляемом режиме | Модификатор выбранной характеристики + вклад владения + дополнительный бонус; компетентность удваивает бонус мастерства |
| Спасбросок | Модификатор характеристики + бонус мастерства при владении |
| Инициатива персонажа | Модификатор Ловкости + дополнительный бонус |

Навыки поддерживают ручной и вычисляемый режимы. Класс брони отображается из сохранённого значения; редактирование переводит его в ручной режим. Пользовательские черты хранят название и описание; сами по себе они не применяют игровые эффекты.

Хиты и потраченные кости хитов редактируются вручную. Расход ячеек ограничен диапазоном от 0 до их максимума. Использование предмета уменьшает его количество на 1, если оно больше нуля.

Скорость задаётся одним неотрицательным числом в `combat.speed` и редактируется одним полем «Скорость».

## Модель данных и хранение

Основной контракт `Character` описан в [src/types/character.ts](src/types/character.ts). Сущности не содержат поля `id`. Для старых сохранений поддерживается необязательная отметка `schemaVersion: 3`.

| Часть модели | Содержимое |
| --- | --- |
| `identity`, `origin` | Общие сведения и происхождение персонажа |
| `abilities`, `proficiency`, `savingThrows`, `skills` | Характеристики, владения, спасброски и навыки |
| `combat`, `attacks` | Боевые ресурсы и атаки |
| `spellcasting` | Известные и подготовленные заклинания, заговоры и ячейки |
| `inventory`, `personality` | Предметы, деньги, биография и заметки |
| `feats` | Пользовательские черты с названием и описанием |
| `extensions` | Дополнительные данные сохранённого листа |
| `encounters` | Необязательные данные боевых сцен |

Вид, класс, черты, заклинания и предметы заполняются вручную. Встроенных справочников, подбора по правилам и данных развития в модели нет. Проверяются структура листа и значения полей. Подготовка хранится в булевом поле `prepared` известного заклинания. Редактирование и удаление записей используют ссылки на объекты; одинаковые названия допустимы. Ключи отображения Vue хранятся отдельно от сущностей в `WeakMap` и не попадают в сохранение.

### Контракт браузерного хранилища

Чтение и запись реализованы в [src/api/characterStorage.ts](src/api/characterStorage.ts).

| Хранилище | Ключ | Значение |
| --- | --- | --- |
| `localStorage` | `nastolka:character-sheet` | JSON одного персонажа |
| `sessionStorage` | `nastolka:sheet:active-tab` | `main`, `combat`, `magic`, `inventory` или `bio` |

Чтение и сохранение используют единый ключ `nastolka:character-sheet`. Если записи нет, создаётся пустой лист. При чтении прежнее поле урона атаки (строка или неотрицательное число) переносится в первую запись списка `damages` с нулевым дополнительным уроном и без характеристики. Прежние общий тип урона и флаг владения атаки переносятся во все её строки, в которых ещё нет соответствующих полей. Устаревшие поля типа урона, владения, характеристики и дополнительного бонуса удаляются из самой атаки. Прежние массивы свойств предметов объединяются в строку через запятую. Затем данные проверяются в текущем формате. Другие преобразования сохранений и загрузка по прежним ключам не поддерживаются.

Перед использованием прочитанных данных и перед записью выполняется проверка через [src/validation/characterValidation.ts](src/validation/characterValidation.ts). В секции `combat` проверяется скорость; ограничения остальных полей задаются в интерфейсе. Данные остаются в браузере и не синхронизируются между устройствами.

## Устройство проекта

### Запуск приложения

1. [src/main.ts](src/main.ts) подключает глобальные стили, создаёт Vue-приложение и регистрирует Naive UI.

### Изолированный модуль монстра

`src/modules/monster` содержит отдельный лист монстра. Единственная публичная точка входа — `src/modules/monster/index.ts`: компонент `MonsterSheet`, composable `useMonsterSheet` и типы `Monster`, `MonsterAbilityKey`, `MonsterAbilityScore`, `MonsterSkillRecord`, `MonsterAttackRecord`, `MonsterAttackDamageRecord`.

Внутри модуля расположены собственные `api`, `components`, `composables`, `data`, `domain`, `modules`, `types`, `utils` и `views`. Локальные импорты не выходят за его пределы; компоненты используют установленные Vue и Naive UI, оформление — Tailwind. Состояние листа общее для компонентов модуля и не связано с состоянием персонажа.

Контракт содержит строковый `level`, русские ключи характеристик с `score`, `modifier` и `proficient`, навыки, хиты, поле «Макс.Хиты» (`bloodiedHitPoints`), инициативу, КД, скорость, текстовое снаряжение и особенности. Если в сохранении нет `bloodiedHitPoints`, при загрузке оно получает значение 0. Устаревшее текстовое поле `savingThrow` удаляется при загрузке. Текстовые поля сохраняются как есть, включая `<br>`.

Характеристики отображаются как у персонажа: значение, вычисляемый модификатор, спасбросок и флажок владения. Поле `modifier` пересчитывается из `score` при загрузке и изменении значения в листе; отсутствующий в старых сохранениях `proficient` получает значение `false`. Бонус владения рассчитывается как у персонажа по числовому уровню от 1 до 20; при другом значении уровня зависимые от владения бонусы не вычисляются.

Навыки хранятся в `skills: MonsterSkillRecord[]`. Новый монстр и старые сохранения без этого поля получают 18 стандартных навыков без владения. Блок повторяет лист персонажа: две колонки с раскрывающимися настройками связанной характеристики, владения или экспертизы, автоматического либо ручного расчёта и дополнительной целочисленной поправки. Навыки и владение спасбросками сохраняются вместе с листом.

Атаки хранятся в `attacks: MonsterAttackRecord[]`; в старых сохранениях отсутствующий список заменяется пустым. Во вкладке «Бой» атаки создаются, редактируются в раскрывающемся списке и удаляются так же, как в листе персонажа. Каждая атака содержит название, тип, дистанцию, описание и список строк урона. В строке урона сохраняются текст урона, его тип, дополнительный целочисленный урон, необязательная характеристика монстра (`Сил`, `Лов`, `Мдр`, `Тел`, `Инт`, `Хар`) и флаг добавления бонуса владения. Строки урона можно добавлять и удалять. Атаки сохраняются вместе с остальными данными через `useMonsterSheet().save()`.

Уровень, размер, тип существа, опыт и флаг лидера редактируются над вкладками. Вкладка «Основное» содержит раскрывающиеся блоки характеристик и навыков, «Бой» — боевые параметры и атаки, «Описание» — текстовые поля снаряжения и особенностей. Методы `load`, `save` и `createMonster` доступны через `useMonsterSheet`; загрузка и сохранение используют отдельный ключ `localStorage` — `nastolka:monster-sheet`. Неудачное сохранение оставляет изменения доступными для повторной попытки.

## Технологии и команды

Основной стек: Vue 3, TypeScript 5.9, Vite 7, Tailwind CSS 4, Naive UI и Iconify. Состояние листа хранится в Vue refs и computed внутри `useCharacterSheet`. Версии зависимостей и команды определены в [package.json](package.json), зафиксированные версии - в `package-lock.json`. Пакетный менеджер - npm.

| Команда | Назначение |
| --- | --- |
| `npm install` | Установка зависимостей |
| `npm run dev` | Локальный сервер Vite |
| `npm run typecheck` | Проверка TypeScript через `vue-tsc -b` |
| `npm run lint` | Проверка ESLint |
| `npm run format` | Исправления ESLint и форматирование файлов TypeScript, Vue и CSS внутри `src` через Prettier |
| `npm run build` | Проверка TypeScript и production-сборка в `dist` |
| `npm run preview` | Локальный просмотр готовой сборки |
| `npm run deploy` | Публикация предварительно собранного `dist` через `gh-pages` |

При установленных зависимостях для запуска достаточно `npm run dev`. Сборка и локальный просмотр выполняются последовательно:

```sh
npm run build
npm run preview
```

Перед публикацией нужно выполнить `npm run build` с подходящим `VITE_BASE`. Команд `test` и `gen` сейчас нет.

| Переменная | Где используется | Поведение |
| --- | --- | --- |
| `VITE_BASE` | [vite.config.ts](vite.config.ts), окружение процесса сборки | Базовый путь приложения; без значения используется `/`, а при `GITHUB_ACTIONS=true` - `/dnd5v/` |
