# Nastolka D&D 5: спецификация проекта

`nastolka-dnd-5-sheet` - браузерный лист персонажа D&D 5 с локальным сохранением и справочниками редакции 2024 года.

README описывает назначение приложения, пользовательские сценарии, модель данных, устройство модулей и ограничения текущей реализации. Общие правила написания кода и работы с репозиторием находятся в [AGENTS.md](AGENTS.md). При изменении возможностей проекта здесь обновляются соответствующие разделы спецификации.

## Назначение и границы приложения

Приложение открывает один лист персонажа и позволяет редактировать его характеристики, боевые параметры, заклинания, снаряжение и биографию.

Текущий лист работает без backend. Авторизация, игровые комнаты, совместное редактирование и серверная синхронизация не подключены. Vue Router, Pinia, Pinia Colada и генерация API через Orval в текущем приложении отсутствуют.

## Пользовательские возможности

В шапке листа редактируются основные сведения о персонаже: имя, вид, класс, подкласс, уровень, опыт и мировоззрение. Здесь же отображается состояние сохранения.

| Раздел | Возможности |
| --- | --- |
| Основное | Шесть характеристик, спасброски, навыки, особенности вида и класса, пользовательские черты |
| Бой | Класс брони, инициатива, скорость, хиты, кости хитов, спасброски от смерти, атаки, короткий и продолжительный отдых |
| Магия / Заклинания | Заклинания и заговоры, подготовленные заклинания, ячейки уровней 1-9 и учёт их расходования |
| Инвентарь | Предметы, количество, вес, экипировка, расходование предметов и монеты пяти номиналов |
| БИО | Черты характера, идеалы, привязанности, слабости, биография и дополнительные заметки |

Атаки, заклинания, заговоры, предметы и пользовательские черты удаляются сразу, без подтверждения. Удаление сохраняется вместе с остальными изменениями листа.

### Загрузка и сохранение

- При открытии приложение читает сохранённый лист. Если записи нет, создаётся пустой персонаж первого уровня с `id: '1'`; до первого сохранения он находится только в памяти.
- Обычные изменения сохраняются кнопкой сохранения. Несохранённые изменения определяются сравнением листа с последним сохранённым снимком.
- Короткий и продолжительный отдых, изменение расхода ячеек и успешное расходование предмета вызывают сохранение сразу после действия.
- При закрытии страницы с несохранёнными изменениями приложение запрашивает стандартное предупреждение браузера.
- Ошибки чтения и записи отображаются отдельно. При ошибке загрузки доступны повторная попытка и создание нового персонажа.
- Создание нового персонажа заменяет текущий лист. Если персонаж уже загружен или возникла ошибка загрузки, действие требует подтверждения.
- Выбранная вкладка запоминается в `sessionStorage`; неизвестное значение заменяется на «Основное».

## Игровые расчёты

Ниже зафиксировано поведение текущей реализации. Основные функции находятся в [src/domain](src/domain).

| Показатель | Расчёт |
| --- | --- |
| Модификатор характеристики | `floor((значение - 10) / 2)` |
| Бонус мастерства | +2 на уровнях 1-4, +3 на 5-8, +4 на 9-12, +5 на 13-16, +6 на 17-20 |
| Навык в вычисляемом режиме | Модификатор выбранной характеристики + вклад владения + дополнительный бонус; компетентность удваивает бонус мастерства |
| Спасбросок | Модификатор характеристики + бонус мастерства при владении |
| Бонус атаки в вычисляемом режиме | Модификатор выбранной характеристики + бонус мастерства при владении + дополнительный бонус |
| Инициатива персонажа | Модификатор Ловкости + дополнительный бонус |

Навыки и атаки поддерживают ручной и вычисляемый режимы. Класс брони отображается из сохранённого значения; редактирование переводит его в ручной режим. Пользовательские черты хранят название и описание; сами по себе они не применяют игровые эффекты.

Короткий отдых расходует выбранное количество доступных костей хитов. Каждая кость восстанавливает результат броска плюс модификатор Телосложения, минимум 1 хит; итоговые хиты ограничены максимумом персонажа. Для броска требуется распознаваемый размер кости.

Продолжительный отдых восстанавливает текущие хиты до максимума, обнуляет временные хиты, потраченные кости хитов, спасброски от смерти и расход ячеек заклинаний. Расход ячеек ограничен диапазоном от 0 до их максимума. Использование предмета уменьшает его количество на 1, если оно больше нуля.

## Модель данных и хранение

Основной контракт `Character` описан в [src/types/character.ts](src/types/character.ts). Текущая версия схемы - `schemaVersion: 3`.

| Часть модели | Содержимое |
| --- | --- |
| `identity`, `origin` | Общие сведения и происхождение персонажа |
| `abilities`, `proficiency`, `savingThrows`, `skills` | Характеристики, владения, спасброски и навыки |
| `combat`, `attacks` | Боевые ресурсы и атаки |
| `spellcasting` | Известные и подготовленные заклинания, заговоры и ячейки |
| `inventory`, `personality` | Предметы, деньги, биография и заметки |
| `feats`, `features`, `progression` | Пользовательские черты, ссылки на особенности из каталога и данные развития |
| `extensions.characterCreation` | Данные выбора при создании персонажа |
| `encounters` | Необязательные данные боевых сцен |

Справочники редакции 2024 года находятся в [src/data/rules2024](src/data/rules2024), контракты правил - в [src/types/rules.ts](src/types/rules.ts). Модель сочетает ссылки на справочники с пользовательскими текстовыми записями. Наличие данных развития и каталогов не означает автоматического применения всех правил класса или полной прогрессии заклинаний.

### Контракт браузерного хранилища

Чтение и запись реализованы в [src/api/characterStorage.ts](src/api/characterStorage.ts).

| Хранилище | Ключ | Значение |
| --- | --- | --- |
| `localStorage` | `nastolka:character-sheet` | JSON одного персонажа |
| `sessionStorage` | `nastolka:sheet:active-tab` | `main`, `combat`, `magic`, `inventory` или `bio` |

Если основной записи нет, чтение проверяет прежний ключ активного персонажа `nastolka:character-sheet:active` и соответствующую запись `nastolka:character-sheet:<id>`. При отсутствии ключа активного персонажа проверяются записи `nastolka:character-sheet:1` и `nastolka:character-sheet:demo-character`. Пустое значение прежнего активного идентификатора означает отсутствие выбранного персонажа.

После сохранения используется единый ключ `nastolka:character-sheet`; старые записи остаются нетронутыми. Это совместимость с прежними ключами хранения, а не преобразование старых версий схемы: валидатор принимает только версию 3.

Перед использованием прочитанных данных и перед записью выполняется проверка через [src/validation/characterValidation.ts](src/validation/characterValidation.ts). Секция `combat` этой проверкой не валидируется; ограничения полей задаются в интерфейсе. Данные остаются в браузере и не синхронизируются между устройствами.

## Устройство проекта

### Запуск приложения

1. [src/main.ts](src/main.ts) подключает глобальные стили, создаёт Vue-приложение и регистрирует Naive UI.
2. [src/App.vue](src/App.vue) задаёт русскую локализацию, провайдеры уведомлений, диалогов и модальных окон.
3. [src/views/CharacterSheetPage.vue](src/views/CharacterSheetPage.vue) отображает лист персонажа.
4. [useCharacterSheet](src/composables/useCharacterSheet.ts) управляет загрузкой, изменениями, игровыми действиями и сохранением.

| Путь | Назначение |
| --- | --- |
| `src/views` | Страница листа персонажа |

| `src/domain` | Игровые расчёты и операции над данными |
| `src/api` | Работа с локальным хранилищем персонажа |

## Технологии и команды

Основной стек: Vue 3, TypeScript 5.9, Vite 7, Tailwind CSS 4, Naive UI и Iconify. Состояние листа хранится в Vue refs и computed внутри `useCharacterSheet`. Версии зависимостей и команды определены в [package.json](package.json), зафиксированные версии - в `package-lock.json`. Пакетный менеджер - npm.

| Команда | Назначение |
| --- | --- |
| `npm install` | Установка зависимостей |
| `npm run dev` | Локальный сервер Vite |
| `npm run typecheck` | Проверка TypeScript через `vue-tsc -b` |
| `npm run lint` | Проверка ESLint |
| `npm run format` | Исправления ESLint и форматирование файлов TypeScript, Vue и CSS внутри `src` через Prettier |
| `npm run build` | Проверка TypeScript и production-сборка в `dist` |
| `npm run preview` | Локальный просмотр готовой сборки |
| `npm run deploy` | Публикация предварительно собранного `dist` через `gh-pages` |

При установленных зависимостях для запуска достаточно `npm run dev`. Сборка и локальный просмотр выполняются последовательно:

```sh
npm run build
npm run preview
```

Перед публикацией нужно выполнить `npm run build` с подходящим `VITE_BASE`. Команд `test` и `gen` сейчас нет.

### Окружение и ресурсы

| Переменная | Где используется | Поведение |
| --- | --- | --- |
| `VITE_BASE` | [vite.config.ts](vite.config.ts), окружение процесса сборки | Базовый путь приложения; без значения используется `/`, а при `GITHUB_ACTIONS=true` - `/dnd5v/` |
| `VITE_APP_API` | [useSocketFactory.ts](src/composables/useSocketFactory.ts) | Адрес для общего Socket.IO Manager; текущему локальному листу не требуется |

В [.env.example](.env.example) осталась переменная `VITE_ASSET_BASE_URL`, которая в текущих исходниках не используется. Алиас `@` указывает на `src`. Глобальные стили подключаются через [src/styles/index.css](src/styles/index.css).
